# DB 설계

데이터 모델링과 DB 설계 검토에 이 스킬을 사용합니다.

## 산출물

- 엔티티 모델
- ERD
- 스키마 정의서
- 테이블 설계
- 관계 설명
- 인덱스 전략
- 마이그레이션 계획
- 보존/삭제/감사 정책

## Application Architecture agent와의 관계

이 스킬은 Application Architecture agent의 주 스킬입니다.

`detail-design` 스킬과 함께 사용하며, 프로그램 정책과 권한이 DB 구조에 반영되었는지 `templates/application-data-contract.md`를 기준으로 확인합니다.

## 작업 절차

1. 요구사항, API 명세, 아키텍처를 확인합니다.
2. 프로그램 상세 설계서와 `application-data-contract.md`를 확인합니다.
3. 엔티티, 관계, 생명주기, 소유권을 식별합니다.
4. 테이블, 컬럼, 제약조건, 인덱스를 정의합니다.
   - 컬럼 표는 테이블별로 분리합니다.
   - DB에서 강제할 제약과 애플리케이션에서 강제할 정책을 구분합니다.
5. 마이그레이션, 보존 정책, 감사, 성능을 고려합니다.
6. 정책, 권한, 상태, 이력 요구사항이 DB 설계에 반영되었는지 확인합니다.
7. 데이터 관련 리스크와 오픈 이슈를 기록합니다.

## 작성 기준

- 스키마 정의서는 테이블별 컬럼 표를 기본으로 합니다.
- 각 테이블은 PK, FK, unique, check, index 후보를 명확히 가집니다.
- 이력/감사 테이블은 기록 시점, 기록 항목, 변경자, 보존 정책을 포함합니다.
- soft delete, hard delete, archive, restrict, cascade 중 삭제 정책을 명시합니다.
- 프로그램 정책 중 DB 제약으로 막을 수 있는 것과 애플리케이션 로직으로만 막을 수 있는 것을 구분합니다.
- 보존 기간, 개인정보, 감사 로그 범위가 불명확하면 오픈 이슈로 남깁니다.
