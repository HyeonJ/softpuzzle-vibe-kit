# 프로그램 상세 설계

복잡한 기능을 구현하기 전에 이 스킬을 사용합니다.

## Application Architecture agent와의 관계

이 스킬은 Application Architecture agent의 주 스킬입니다.

`db-design` 스킬과 함께 사용하며, 두 스킬 사이에서 공유해야 하는 엔티티, 상태, 권한, 이력, 보존 정책은 `templates/application-data-contract.md`에 기록합니다.

## 산출물

- 모듈 설계
- 프로그램 설계서
- 정책 정의
- 권한 정의
- 상태 흐름
- 서비스 흐름
- 예외 케이스 목록
- 데이터 영향
- 구현 체크리스트

## 작업 절차

1. 아키텍처, API 명세, DB 설계, 화면정의서를 확인합니다.
2. 모듈의 책임과 경계를 정의합니다.
3. 입력, 출력, 오류, 부수 효과를 명시합니다.
4. 정책, 권한, 상태 전이, 예외 케이스를 문서화합니다.
   - 정책은 ID, 우선순위, 적용 조건, 예외, 실패 status를 함께 둡니다.
   - 권한은 역할, 대상, 행위, 현재 상태, 목표 상태를 분리합니다.
   - 상태 변경은 현재 상태와 목표 상태를 구분합니다.
   - no-op 성공 조건과 이력 저장 제외 조건을 명시합니다.
5. 데이터 생성/수정/삭제 영향과 이력 필요 여부를 정리합니다.
6. API/Backend/Frontend로 넘길 endpoint, schema, error, auth 요구사항을 정리합니다.
7. `application-data-contract.md`에 DB 설계와 공유할 결정을 기록합니다.
8. 기존 코드베이스 패턴에 맞춰 설계를 유지합니다.

## 작성 기준

- 정책 문장은 구현자가 조건문으로 옮길 수 있을 만큼 구체적이어야 합니다.
- 권한 정책은 `누가`, `무엇을`, `어떤 상태에서`, `어떤 상태로` 바꿀 수 있는지 드러나야 합니다.
- 400, 401, 403, 404, 500을 구분할 수 있도록 예외 케이스를 작성합니다.
- 감사/이력 요구사항은 저장 대상, 저장 시점, 저장 제외 조건을 포함합니다.
- API 계약이 필요한 기능은 `api-contract-handoff.md`로 넘길 수 있는 수준의 endpoint 후보와 schema 후보를 남깁니다.
