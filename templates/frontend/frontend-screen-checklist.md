## 요구사항 반영

- [ ] 관련 기능 요구사항을 확인했습니다.
- [ ] 관련 비기능 요구사항을 확인했습니다.
- [ ] 인수 기준을 확인했습니다.
- [ ] 범위 밖 항목을 구분했습니다.
- [ ] 오픈 이슈를 기록했습니다.

## UI/퍼블리싱

- [ ] 화면정의서 또는 Figma의 핵심 구조를 반영했습니다.
- [ ] 기존 디자인 시스템 또는 컴포넌트를 우선 검토했습니다.
- [ ] 디자인 토큰을 우선 사용했습니다.
- [ ] 임의 색상과 임의 간격 사용을 피했습니다.
- [ ] 텍스트가 이미지 안에 baked-in 되지 않습니다.
- [ ] 디자인과 다르게 구현한 부분을 기록했습니다.

## 반응형

- [ ] 모바일 크기에서 주요 흐름을 확인했습니다.
- [ ] 태블릿 크기에서 주요 흐름을 확인했습니다.
- [ ] 데스크톱 크기에서 주요 흐름을 확인했습니다.
- [ ] 텍스트가 겹치거나 잘리지 않습니다.
- [ ] 버튼, 카드, 표, 패널 크기가 상태 변화로 흔들리지 않습니다.

## 접근성

- [ ] 의미에 맞는 HTML 요소를 사용했습니다.
- [ ] 버튼과 링크 역할을 구분했습니다.
- [ ] 폼 입력에 label 또는 접근 가능한 이름이 있습니다.
- [ ] 이미지 alt를 목적에 맞게 작성했습니다.
- [ ] 키보드로 주요 인터랙션에 접근할 수 있습니다.
- [ ] 색상만으로 상태를 전달하지 않습니다.

## 화면 상태

- [ ] loading 상태를 처리했습니다.
- [ ] empty 상태를 처리했습니다.
- [ ] success 상태를 처리했습니다.
- [ ] error 상태를 처리했습니다.
- [ ] permission denied 상태를 처리했습니다.
- [ ] 필요 없는 상태는 제외 사유를 기록했습니다.

## API 연동

- [ ] 화면에서 사용하는 endpoint를 확인했습니다.
- [ ] 요청 파라미터를 확인했습니다.
- [ ] 응답 데이터를 화면에 매핑했습니다.
- [ ] 오류 응답을 처리했습니다.
- [ ] mock API와 real API 상태를 구분했습니다.
- [ ] 중복 요청 방지 또는 취소가 필요한지 검토했습니다.

## 폼/검증

- [ ] 필수 입력값을 표시했습니다.
- [ ] 형식 검증을 구현했습니다.
- [ ] 제출 중 중복 submit을 방지했습니다.
- [ ] 서버 검증 오류를 표시했습니다.
- [ ] 제출 실패 시 입력값을 보존합니다.
- [ ] 성공 후 후속 동작을 정의했습니다.

## 라우팅/권한

- [ ] route path가 IA와 일치합니다.
- [ ] deep link 진입을 고려했습니다.
- [ ] 인증이 필요한 화면의 guard를 처리했습니다.
- [ ] 권한 없는 사용자의 상태를 처리했습니다.
- [ ] 잘못된 경로 또는 삭제된 리소스 처리를 확인했습니다.
